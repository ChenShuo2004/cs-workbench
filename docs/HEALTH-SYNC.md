# Health → CS 工作台同步

## 运行方式

这是 Codex 定时浏览器同步，不是 ChatGPT Health 官方 API，也不是实时 HealthKit 连接。
已配置本对话的 Codex heartbeat「同步 Health 到 CS 工作台」（ID `health-cs`），每 15 分钟尝试运行。Mac、Codex、Chrome 及 ChatGPT 登录状态需要可用；未来计划执行结果须以每次真实运行的状态为准。
暂停、恢复、修改频率在 Codex 自动任务中操作，不添加系统 cron 或 LaunchAgent。

## 每次读取

1. 用 `cua_repl` 的受支持 Chrome 浏览器接口复用/打开 `https://chatgpt.com/health`。刷新页面；账户页核实 Apple 健康“已连接”。首页读取当前实际可见卡片，不读取登录令牌、不请求私有 API。
2. 只采集下表指标。逐一打开指标详情，读取历史图中明确可见的测量标签（原始日期、原值、原单位），补齐当前 UI 可访问的全部历史窗口，不能只取首页最新一天。若有可见的日期范围或翻页入口，再扩展读取；没有入口不能推断更早历史。数值必须来自指标卡片或图表测量点，不来自下方 AI 解读、建议或聊天回答。日期使用页面原始日期；只有年月时保留 `YYYY-MM`。缺失不填零，历史日期不换成今天；不要将区间平均值误录为一天的值。
3. 通过 stdin 传入 JSON，由本机脚本校验、换算、去重、原子保存。一次观察中的任一记录无效则整批不写入。不把健康数据放进仓库或内容项目。

| metric | 含义 | 允许原始 unit |
| --- | --- | --- |
| steps | 步数 | count、/d |
| distance | 步行与跑步距离 | km、mi |
| weight | 体重 | kg、lb |
| sleep | 睡眠时长 | h、min |
| restingHeartRate | 静息心率，不能用普通心率代替 | bpm、/min |

导入命令：`/opt/homebrew/bin/node /Users/chenshuo/coding/cs-workbench/scripts/health-sync.cjs import`

stdin 结构（以下是类型说明，不是可导入的示例健康数据）：
```
{
  sourceUrl: "https://chatgpt.com/health?tab=home",
  appleHealthConnected: true,
  observedAt: 本轮读取时间的 ISO 字符串,
  records: [{ metric: 上表键, value: 原始数字, unit: 原始单位, date: 原始日期 }]
}
```

原始单位保存在来源标签，英里按 1.609344 换算公里、磅按 0.45359237 换算公斤，保留两位小数。每轮检查历史缺口与上游修订，即使最新日期没有推进，也要补齐中间日期并更新修订值。导入器按 `metric + date + source` 去重，最多 500 条一批；本轮 `recordCount` 应等于实际导入条数，不固定为 5。只能声称补齐当前网页明确可见的范围，不能声称拥有全部 Apple 健康历史。不再展示需要用户补录的主观精力。

同指标同日出现多条不同测量，而 UI 没有明确日汇总或足够时间信息时，现有日值模型无法无损容纳它们。将完整原始观察与冲突原因保存到本机私有 `health/observations/`（目录 0700、文件 0600），跳过该冲突日期的日值导入，不取最后值、不平均、不臆造日期。原始观察不保存到仓库或内容项目。原有月份精度记录保留；新增准确日期并不授权删除旧记录。

## 成功、失败与验收

`health-sync.cjs status` 只打印同步元数据与记录数量，不打印指标值。
`health-sync.cjs fail` 从 stdin 接收 `{"error":"简短的真实失败原因"}`，保留原数据和最近成功时间。
`health-sync.cjs configure` 从 stdin 接收实际已创建的 `automationId` 和可读的 `scheduleLabel`。配置成功不等于同步成功。

每次必须核实导入退出码、`lastSuccessAt`、`recordCount`，并逐条比对本轮观察与入库记录的日期和换算值；关注缺失日期是否真正补齐、修订值是否更新。失败必须写入 fail；若浏览器/工具不可用，不能使用旧观察冒充新同步。同样的失败或无新数据保持安静，首次失败、原因变化、恢复或确实需要用户行动时通知。最新日记录超过 3 天提示上游陈旧一次，不重复打扰。

本机文件：`~/Library/Application Support/CS 工作台 Pro/health/records.json`。包含 records 和 sync，文件权限 0600，`.previous` 是前一次备份；写入由排他锁保护。若进程意外中断留下 `.write-lock`，先核实没有其他写入进程并检查原文件与备份，再恢复，不能盲删锁。
Health 页和首页每 30 秒及重新聚焦时读取本机文件。页面分别显示最近成功时间、上游记录日期与错误；超过 45 分钟未成功会提醒检查同步。显示的任务频率是配置说明，任务实际启停状态以 Codex 为准。

“刷新本地记录”立即重读本机文件，不触发网页采集。点击后显示读取状态并禁止重复点击；完成后显示本地检查时间、记录是否变化与最新记录日期。未变化时明确提示“没有新的本地记录”，本地读取不修改网页采集成功时间。读取失败或超过 15 秒时保留原卡片并提供重试；定时读取、聚焦读取与手动读取共享同一进行中的请求，避免旧响应覆盖新记录。

## 本地验证

`npm test` 与 `npm run build`。测试用临时目录，覆盖单位转换、月份精度、重复执行不改记录时间、失败保留数据、无效整批回滚和并发锁拒绝。
CLI 可通过 `CS_HEALTH_DATA_DIR` 指向独立验收目录；不要用假数据测试真实用户目录。

## 限制

- 浏览器界面变化、断网、登出、Mac 休眠或 Codex 关闭可能使计划不能完成，恢复后以实际成功时间为准。
- 若 Health 自身没有新数据，本机不能创造更新。需要手机端继续向 Apple 健康写入并由 ChatGPT Health 上游同步。
- 历史补齐受网页可见范围限制，不包含不可见的全量 HealthKit 导出、诊断、医疗提醒或多平台健康数据直连。
